Design system

Your files, at home. Arca is a personal drive with its own engine: one user, their own devices and a hub they choose. The interface is quiet, exact and green like the icon it starts from. Every specimen on this page is rendered with the production stylesheets, so what you see is what ships.

Iconography 04

Lucide, stroke 1.75, round caps. 16 px in rows and buttons, 20 px in navigation and dialogs, 24 px in empty states. Icons take the text colour next to them; only state icons carry colour.

Elevation

Menu Dialog

Flat with a border by default. Shadows only for things that float: menus, dialogs, the window (--shadow-window; in dark they also sit on a raised fill with a hairline ring), the mobile scrub thumb.

Motion

Fast 120 ms, enter 200 ms, exit 140 ms, one ease. Desktop route changes fade and lift in over 200 ms and dialogs, menus and notices enter 8 px up (dialogs also from 0.985) and dismiss at once; mobile tabs fade, details push 30 dp, sheets slide from the edge, dialogs scale from 0.9. Only opacity and transform animate; reduced motion collapses to zero. The busy grid is the only loop.

Components · desktop and web 06

Buttons

One primary per screen, 32 px controls. Back, text and ghost buttons are borderless green actions. Pressed: secondary and icon buttons fill with the hover tone, primary drops to 85% opacity; on a touch screen icon buttons grow to 44 px. Destructive actions are red, name the action and always say what stays.

Voice and rules 09

Plain, exact, calm

Say what happened, where and when. No exclamation marks, no adjectives: “Up to date · verified 2 min ago”, never “All safe!”. English in the product; user names, paths and content are never translated.

Green means verified

Only a completed, hash-checked state gets the green fill. Working states use the busy grid in green text until the last byte lands.

Unknown is never zero

A missing count reads “Not counted yet”; an unknown total is indeterminate. Never simulate a percentage or invent event metadata.

Loading never counts

Known chrome renders for real; each loading section shows exactly one row sized like a real one. Views keep their content while refreshing.

Scroll in galleries, Show more in lists

Galleries load as you scroll, in both directions, with no button. Files, History and a file's versions append rows under one Show more button.

One placeholder

Media without a thumbnail uses the placeholder token and a soft image or play glyph on every surface, desktop and mobile.

Devices show their own files

Thumbnails, the viewer and video always read the copy on this device or phone. The hub provides synchronization and metadata, never the pixels of a current photo; what is not downloaded yet stays a placeholder.

Hub creates, devices start syncing

“Create shared folder”, “Pair a device” and “Remove device” appear only while managing the hub. Everywhere else the verb is “Start syncing”, and it always asks for a local destination and shows what it needs.

Destructive actions say what stays

Stop syncing, delete and cleanup confirm in a dialog with a red, named action and state what is kept: files on disk, on the hub, in history.

Notices, dialogs, banners

Notice: transient, never blocks. Dialog or sheet: a decision now, always with an explicit Cancel or Close. Banner: a persistent condition of the current screen. Mobile has no standing “Offline” line; the connection notice covers it.

Codes, not passwords

Pairing and web access use separate six-digit, single-use, ten-minute codes. Credentials stay long-lived and revocable.

Four different facts

Network reachable, Arca detected, sync completed and backup received are separate facts. Never collapse them into one dot.

Mono for facts

Paths, hashes, ports, versions and section labels are Fragment Mono so they read as data, not prose.
