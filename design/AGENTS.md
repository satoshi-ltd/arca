# Design kit — agent instructions

`design/` is Arca's visual reference, never a status page. It is a self-contained module: open or publish the folder alone and every page works. The root `AGENTS.md` says when to touch it; this file is the contract for what is inside.

## Layout

| Path | Role |
| --- | --- |
| `index.html`, `desktop.html`, `mobile.html`, `proposals.html` | The pages, hand-authored |
| `kit.css`, `kit.js`, `mobile.css` | Kit-only styles and behaviour; colours and sizes come from tokens, never literals |
| `mobile-tokens.css`, `favicon.svg` | Generated by `build.js`; never edited by hand |
| `build.js` | The single generator entry point |
| `AGENTS.md`, `CLAUDE.md` | This contract; `CLAUDE.md` is `@AGENTS.md` |

Arca's particularity: the pages are hand-authored from the production tokens and markup (`apps/desktop/src/tokens.css`, `style.css`, `app.js`), so there is no board source file and no page generator. The nav and the Proposals page are maintained in the page sources, and the proposal boards live in `proposals.html` itself.

## Tabs

Every page carries the same nav in the same order and marks only itself with `aria-current="page"`: `System` (`index.html`: tokens and components), `Desktop` (`desktop.html`, desktop and web), `Mobile` (`mobile.html`), then `Proposals` (`proposals.html`). A new interface adds its own tab before Proposals. There is no Open work page or tab: ROADMAP is already readable.

## Proposals

`Proposals` holds purely visual ideas only while they are proposals; with no boards the page shows its "No proposals" empty state (`class="kit-empty"`). A board is exactly:

```html
<article class="kit-board" data-board="ID">
```

with, in this order: the ID (`<code>ID</code>`), the area, the title (`<h3>`), the why (`<strong>Why.</strong>`), a "Now" drawing of what exists (`<figcaption>Now</figcaption>`), a "Proposed" drawing (`<figcaption>Proposed</figcaption>`), both built from the kit's own classes, and what proves it done (`<strong>Accept</strong>`). Board IDs are unique.

## Lifecycle

- Idea: the board only. A purely visual idea is never a Proposed task in ROADMAP; the board is the proposal.
- Approved: the maintainer turns it into one Queue line of type `ui` with the same ID, whose accept is "the board".
- Shipped: the board and its `ui` line are deleted together, in the same change as the code, the regenerated and updated pages, the changelog and SPEC.
- Split rule: a task that mixes logic and a screen splits in two. The screen is board `UI-<TASKID>` with its `ui` line; the logic stays under `<TASKID>` and its accept carries the line "the interface follows board UI-<TASKID>". A board ID never equals the ID of a non-`ui` task.
- Tasks without a visual part (behaviour, data, infra) live only in ROADMAP and never get a board.

## Views in sync

System and every interface tab show what ships; Proposals shows what is proposed. A board left standing after its change shipped, or a page that still draws the old look, fails the adversarial review before the commit.

## Generated files

`npm run design` (`node design/build.js`) writes `mobile-tokens.css` from `apps/mobile/src/palette.js` and `design-tokens.js`, and copies the desktop icon `apps/desktop/src/assets/arca-icon.svg` to `favicon.svg`. `node design/build.js --check` exits non-zero when either output is stale and writes nothing. Run it after changing the mobile palette or geometry, or the icon.

Every page links `favicon.svg` by a path inside `design/`, so the kit stays self-contained.

## Tests and versions

- `tests/design-kit.test.js` fails when the generated tokens or favicon drift, a page does not use the production stylesheets, a page uses a class neither the app nor the kit defines, or kit styles use an undefined token or a literal colour.
- `tests/design-proposals.test.js` fails when a nav differs, a Proposals board is malformed or duplicated, a ROADMAP `ui` task has no board, a board reuses a non-`ui` task ID, or a split task does not cite its board.
- `tests/design-module.test.js` fails when this contract is missing or `scripts/` holds a design file. `CLAUDE.md`, here and at the root, is a local pointer listed in `.gitignore` and never committed; tests read it only where it exists.
- Version banners (`class="kit-version"`) on every page are managed by `scripts/release-manifests.js`; `bump-version.js` moves them and `check-release.js` fails when one lags.
