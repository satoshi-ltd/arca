Proposals

Purely visual ideas, drawn with the kit's own classes, only while they are proposals. A board is the proposal: there is no ROADMAP entry until the maintainer approves it.

Boards 14

UI-MENU-SURFACEDesktop

The folder dropdown is drawn from the same family as the ⋯ menu

Why. Two floating lists sit side by side in the same toolbars and look like different products: the ⋯ menu has generous 8 px padding, the large surface corners and no outline; the dropdown has a hairline border inside its shadow, tight 4 px padding, sharper corners and tiny-radius rows. A dropdown is still a select: it keeps the trigger's width, the green selected row and the check on the right.

Accept Every dropdown (the History folder filter, Settings selects) and the tray's ⋯ menu draw with the ⋯ menu's frame: no border beyond the shadow ring, `--r-surface` corners, 8 px padding, `--r-control` rows; a dropdown keeps the trigger's minimum width, the selected row's tint and the trailing check, and its keyboard focus uses the shared 2 px ring; the tray's literal 18 px line height goes; the System page draws the same dropdown.

UI-SEC-WEB-APPROVAL-REFDesktop

A web sign-in is approved by typing the number the browser shows

Why. The prompt shows the request number and trusts the person to compare it with the browser. Nothing enforces the comparison, and the prompt shows the oldest pending request, which anyone who can reach the hub web can create and keep alive: one Allow on someone else’s request opens a 24-hour administrator session. The proposal stops showing the number and asks for it instead.

Accept The approval prompt on desktop and web shows the browser, address and countdown but never the request number; the six cells use the shared code field with paste and auto-advance; Allow is off until six digits are typed, a number that does not match ends that request with “That number belongs to a different request.” and Deny stays the focused default. The phone follows board UI-SEC-WEB-APPROVAL-REF-MOB.

UI-SEC-WEB-APPROVAL-REF-MOBPhone · Fold

The phone approves a web sign-in by typing the browser’s number

Why. The same gap as on the desktop (board UI-SEC-WEB-APPROVAL-REF): the sheet shows the number, Allow is always on, and the request shown is the oldest one, which may not be yours. On a phone the sheet arrives over whatever you were doing, so a reflex tap is likelier.

Accept The sheet shows the browser, address and countdown but never the request number; the six cells are the pairing code field with the number pad; Allow is off until six digits are typed, a number that does not match ends that request and says so, and the keyboard never covers Deny and Allow.

UI-MASS-DELETEDesktop

A sudden mass disappearance waits for a decision before it is deleted everywhere

Why. When a scan no longer finds a large part of a folder (a disk that came back empty after a reboot, a subfolder moved away, a folder emptied by mistake) the hub records every file as deleted and each device removes its copy, with nothing on screen but a smaller count. Movies & TV keeps no older version to restore. The proposal (decision DEC-MASS-DELETE) holds those deletions and asks.

Accept A scan that would delete more than the agreed share of a folder’s files, or everything under a directory on a different disk than the folder’s root, records nothing and puts the folder in Needs attention with this line and Review; the dialog lists up to five affected directories and “and N more”, Cancel holds the focus, Check again rescans, and Delete from every device records the deletions; the tray lists the folder under Needs attention and the phone shows the same words in its attention row and confirmation.

UI-UX-ERASE-CONFIRMDesktop

Erase asks for the device name, as Delete shared folder asks for the folder’s

Why. Delete shared folder, which keeps every file on disk, makes you type the folder’s name. Erase this hub, which deletes every shared folder, its files and the whole version history, confirms with a single button, and so does Erase this device. The heavier action has the lighter guard.

Accept Erase this hub and Erase this device carry the typed-name field of Delete shared folder under the path list, with the same label pattern, the submit button off until the name matches exactly, and Cancel focused on open; the phone’s Erase confirmation asks for the device name in its sheet.

UI-UX-DESK-WEB-APPROVAL-TRAYDesktop

A web sign-in request reaches a desktop that lives in the tray

Why. The approval prompt opens only in a visible main window. A desktop that runs in the tray, which is the normal state, never learns that a browser is waiting, so the request expires after ten minutes and the person has to find another device or type a web code.

Accept While a request this device may approve is pending, the tray heading takes the warning tone with “Needs your approval” and lists “Web sign-in request · Review” above any folder rows; the row opens the main window on the prompt, the tray icon takes its attention state, and the row leaves when the request is decided or expires.

UI-PAUSE-UNTILDesktop

The window says when a timed pause ends

Why. A pause started from the tray for an hour or until tomorrow reads “Paused until 15:30” in the tray, but the main window’s status card says only “Paused”, the same as a pause with no end, so the window cannot tell you whether sync will come back by itself.

Accept With a timed pause the status card’s second line reads “Until HH:mm · last sync …” (tomorrow or later adds the day) under “Paused”, on one line at the sidebar’s width; an indefinite pause is unchanged; the collapsed rail’s tooltip and the card’s accessible name say “Paused until HH:mm”.

UI-UX-PHOTO-RANGEDesktop

Shift-click selects a range of photos, and a selection can be downloaded

Why. Selecting photos is one click per tile and the bar offers only Delete, so picking fifty photos from a trip is fifty clicks and the only thing to do with them is delete them. Web users have no folder to open, so there is no way to take a set of photos out.

Accept Shift-click selects every tile between the last one toggled and the one clicked, across months, and Shift+Arrow does the same from the keyboard; the bar gains Download after Delete selected…, saving the originals (one file directly, several as an archive named after the folder); Download is off with its reason when the hub is away and the copy is not on this device.

UI-MOB-LIMITED-ACCESSPhone · Fold

Limited photo access offers the way to allow more

Why. With limited access the sheet says “Allow more in system settings.” and stops there: Open settings appears only when access is refused altogether. The person has to leave the app, find Arca in the system settings and come back, for the case the sheet itself tells them to fix.

Accept Under limited photo access the Photo uploads sheet shows Open settings below the warning, as it does when access is refused, and the warning drops its last sentence; on iPhone the button opens the system’s photo selection, on Android the app’s settings; returning to the app refreshes the count. SPEC’s “Open settings only when access is refused” changes with it.

UI-MOB-SELECT-LIMITPhone · Fold

Selecting a 101st photo says why nothing happened

Why. A photo selection stops at 100. The tap on the 101st photo does nothing: no check appears and the bar keeps reading “100 selected”, so it looks like a missed tap and people tap again.

Accept A tap on an unselected photo while 100 are selected leaves the selection unchanged and shows “100 is the most you can select at once.” in the bar’s reason line, announced to screen readers; the line leaves when a photo is unselected; the offline reason takes precedence when both apply.

UI-MOB-ONBOARD-SPACEPhone · Fold

Onboarding warns before the button when the chosen folders do not fit

Why. The last onboarding step shows the download size and the free space side by side in a neutral line and leaves Start syncing on; the refusal comes only after pressing it. The Start syncing sheet already turns the line red and switches the button off for the same case.

Accept When the folders ticked need more than the free space less the 256 MB headroom, the status line reads “Not enough space: X to download · Y free” in the error tone and Start syncing is off with that reason for screen readers; unticking a folder or choosing Stream recomputes it at once; Skip for now stays available.

UI-MOB-MEDIA-TARGETSPhone · Fold

Both players show where you are and let you drag there

Why. The film scrubber is a 4 dp line in a 32 dp strip that seeks only when the finger lifts, and the Now playing line takes taps only: neither shows a handle, so nothing says they can be moved, the position cannot be previewed while dragging, and the film’s target is under the 48 dp touch height.

Accept The film scrubber and the Now playing line draw a 16 dp handle at the position, take a drag as well as a tap in a strip at least 48 dp tall, move the handle and the elapsed time while dragging and seek on release; both stay adjustable for screen readers with their current steps. Without a visible change, the sleep chip, segments, switches, breadcrumbs, the Now playing artist and album links, “Using local Wi-Fi?” and the viewer bar buttons reach 48 dp on Android through hit slop.

UI-MOB-PLAYER-LEGIBLEPhone · Fold

The film’s progress line and times stay readable over a bright picture

Why. The player’s bars are 60% black over the picture. Over snow, sky or a white title card the bar turns mid grey, and the unplayed part of the line (18% white) nearly disappears against it, about 1.5:1, while the 13 sp times sit near 3.9:1. The kit only ever draws the player over a dark still.

Accept In the film player the unplayed track uses the media glyph token and the elapsed and remaining times the on-media token, on the phone and in the desktop and web player’s matching chrome; over a white frame the track reaches 3:1 and the times 4.5:1 against the bar; the kit draws one player over a bright still.

UI-UX-AUTO-EMPTYAuto

The car says what to do when there is no music on the phone

Why. With nothing synced or downloaded, Arca answers the car with three empty tabs and no text, so the head unit draws its own generic empty notice. In the car nobody can tell whether Arca is broken, still loading or simply has nothing to play, and it is the one place where you cannot poke around to find out.

Accept For a library with no playable track the service answers each tab with the message “No music on this phone yet” and the resolution “Open Arca on your phone to sync music”; a streamed library whose hub is away says “Nothing downloaded on this phone” instead; the tabs stay, nothing is playable, and the message leaves as soon as a track is on the phone.

Format 01

Board

One article per idea, tagged with its ID (UI-<TASKID> when it is the screen of a split task). It carries the ID, the area (System, Desktop, Mobile, Auto), a title, why it is worth doing, a "Now" drawing of what exists, a "Proposed" drawing, and what proves it done. A mobile board adds a Fold pair beside its phone pair. Phones sit side by side; desktop, web and Fold drawings stack Now above Proposed so each keeps its full width.

Drawings

Both drawings use production and kit classes only, so the page reads as the app would. A drawing is never a screenshot and never introduces a colour or size outside the tokens.

Lifecycle

Idea: a board only. Approved: one ROADMAP Queue line of type ui with the board ID, whose accept is the board. Shipped: the board and its ui line are deleted together, in the change that ships the code, the updated pages, the changelog and SPEC. A task that mixes logic and a screen splits: the screen is board UI-<TASKID> with its ui line, the logic keeps <TASKID> and its accept says the interface follows that board; a board ID never equals a non-ui task ID.

No visual part

Behaviour, data and infrastructure tasks live only in ROADMAP and never get a board.
