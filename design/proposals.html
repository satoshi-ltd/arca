Proposals

Purely visual ideas, drawn with the kit's own classes, only while they are proposals. A board is the proposal: there is no ROADMAP entry until the maintainer approves it.

Boards 01

UI-MOB-ONBOARD-STREAMPhone · Fold

First folders: music streams, so it adds nothing to download

Why. On Android an Audio library chosen while pairing now streams from the hub, yet this step still says every folder is kept on the phone, adds the library's size to the total and reads Download. Someone with a large music library sees a size they will never download.

Accept On Android, the first-folders step reads “Folders are kept on this phone; music streams. Add more any time.”; an Audio library's row reads “Streams from hub” in place of its file count and size; the caption under the list counts every chosen folder but adds only the size of those that download, as “N GB to download”, followed by the free space; the primary button reads “Start syncing N folders” with the sync icon, or “Start streaming” with the play icon when every chosen folder is an Audio library, and “Choose folders” while nothing is chosen. The iPhone, which still keeps Audio libraries whole, shows today's step unchanged. No other control, text or screen changes.

Format 02

Board

One article per idea, tagged with its task ID. It carries the ID, the area (System, Desktop, Mobile, Auto), a title, why it is worth doing, a "Now" drawing of what exists, a "Proposed" drawing, and what proves it done. A mobile board adds a Fold pair beside its phone pair. Phones sit side by side; desktop, web and Fold drawings stack Now above Proposed so each keeps its full width.

Drawings

Both drawings use production and kit classes only, so the page reads as the app would. A drawing is never a screenshot and never introduces a colour or size outside the tokens.

Lifecycle

Idea: a board only. Approved: one ROADMAP Queue line of type ui with the board ID, whose accept is the board. Shipped: the board is deleted, the changelog and SPEC record it, and this kit is updated.

No visual part

Behaviour, data and infrastructure tasks live only in ROADMAP and never get a board.
