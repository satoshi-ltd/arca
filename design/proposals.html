Boards 01

UI-DEVICES-TABLEDesktop & web · Phone · Fold

Devices as a table: one column per fact, a strong line over a soft one

Why. Every device row packs OS, an occasional version, folders, size and, for the hub, the network and address into one dotted line, then ends in a role chip. Comparing devices means reading each line to find where the version or the size sits, and an outdated client only shows up when its line happens to include a version. The maintainer likes how Tailscale’s Machines page reads: aligned columns under a quiet header, each cell a strong primary line over a soft secondary one, an update-available glyph beside an old version, and no cards. This board adapts that presentation to the data Arca already has, without adding controls.

Technical. No new endpoint, table or report field. /v1/machines already returns per device name, role, backup.enabled, platform, version, selectedFolders, indexedBytes, revoked, lastAddress (the hub’s devices.last_address, set with devices.last_seen on every authenticated replica request), lastContact (devices.last_seen) and the report’s reportedAt. Address: the hub row uses the linked hub URL’s host as today, other rows lastAddress; “Tailscale” is shown when discovery matches that address to a Tailscale peer, otherwise the cell has one line. Version: the platform name only; the report also carries kernelRelease, which is left out (on macOS it is the Darwin kernel number, not the macOS version). Last seen, if kept: “Connected” when lastContact is under 120 s old (the window freshness already uses), else the date and time of lastContact in the style of Hub backup (“Oct 7, 10:01”); the hub row on a replica uses the replica’s own last successful hub request, and with the hub unreachable no other row reads Connected. Desktop renderMachines/deviceRow render a table instead of .device-list; mobile MachineRow renders the stacked cells on the phone and the table on the wide layout. Windows 760 px wide or less use the phone’s stacked rows.

Accept On desktop, web and the unfolded Fold, Devices is a table under a “N devices” pill with the columns Device, Address, Version, Folders, Last seen (if approved) and an actions column, an uppercase mono header and divider-separated rows without cards, tiles or role chips. Every cell is a primary line over a soft secondary line: name with This device over the role text; address over Tailscale when known; version over platform name; folder count over size; a dot with Connected or the date. A version older than the hub’s shows the circled up-arrow in its gutter, warning ink and the tooltip; a removed device reads Removed in danger ink and never shows the up-arrow; an unreported value leaves its cell empty, never 0 or a placeholder. ⋯ appears only where an action exists today: Disconnect… on a replica’s hub row, Allow web approval… and Remove device on the hub’s own page. On the phone each row stacks the same cells without ellipsizing; at 760 px or less desktop does the same. Light and dark use tokens only. No search, filter, add, download or help control is added.

Open questions. 1. Last seen: keep the column, and is “Connected” / “Oct 7, 10:01” the wording, or “Seen 3 h ago” under a day? 2. Role as secondary text (proposed) or keep the Hub / Replica chips in the Device column. 3. Address on the phone: keep it in the stacked row, or leave it for the Fold and desktop and show it on the phone only for the hub.

Format 02

Board

One article per idea, tagged with its task ID. It carries the ID, the area (System, Desktop, Mobile, Auto), a title, why it is worth doing, a "Now" drawing of what exists, a "Proposed" drawing, and what proves it done. A mobile board adds a Fold pair beside its phone pair.

Drawings

Both drawings use production and kit classes only, so the page reads as the app would. A drawing is never a screenshot and never introduces a colour or size outside the tokens.

Lifecycle

Idea: a board only. Approved: one ROADMAP Queue line of type ui with the board ID, whose accept is the board. Shipped: the board is deleted, the changelog and SPEC record it, and this kit is updated.

No visual part

Behaviour, data and infrastructure tasks live only in ROADMAP and never get a board.
