Proposals

Purely visual ideas, drawn with the kit's own classes, only while they are proposals. A board is the proposal: there is no ROADMAP entry until the maintainer approves it.

Boards 01

UI-DESK-SYNC-CONTROLSDesktop

Sync now stays in place while a sync runs

Why. While a folder syncs the sidebar drops Sync now, so the control group shrinks and the button the pointer was on vanishes; SPEC says controls stay stable while loading. It reappears when the sync ends, which reads as flicker. The proposal keeps the button where it is, dimmed with the tooltip “Syncing…”, using the same disabled look the hub-only controls already use.

Accept The sidebar status card shows Pause sync and Sync now in the same positions in every state; while syncing, Sync now is dimmed (aria-disabled, never removed), cannot be activated and its tooltip reads “Syncing…”; when idle or paused it behaves as today.

UI-DESK-SYNC-STATEDesktop

Settings reads synchronization as a state, not as a switch

Why. The Local synchronization card shows the word “Enabled” (or Paused, Disconnected) in the bold title slot with nothing in the control slot, so it reads as a switch that cannot be flipped. Elsewhere in the same card pattern, state is a pill (Connected, Off). The proposal titles the row Synchronization and shows the state as a pill.

Accept The row is titled Synchronization with its description; the state is a pill in the control slot (Enabled in the ok tone with a check, Paused and Disconnected in their existing tones); nothing in the row is interactive.

UI-DESK-MENU-CONSISTENCYDesktop

Menus and dialogs name actions the same way

Why. Remove device sits directly under Allow web approval… in the Devices ⋯ menu, without the separator every other destructive item gets (Delete…, Delete playlist…), and without the ellipsis that marks an action that asks first. The folder menu says Rename while file and playlist menus say Rename…, and its dialog is titled just “Rename” while the others say what is renamed.

Accept Remove device… carries the separator and danger style like the other destructive items, the folder menu reads Rename…, and its dialog is titled Rename shared folder (the submit stays Rename); no other menu or dialog changes.

UI-MOB-CONFIRM-ACTIONSPhone · Fold

A confirmation fits at every text size and says what it does

Why. The confirmation puts Cancel and the action side by side in a 360 dp panel; at the larger text sizes (up to 1.3×) a label such as Delete 2 photos or Stop syncing and delete is wider than the panel and the destructive button gets clipped. The title counts the photos (“Delete 2 photos?”) while the button always says “Delete photo”. The proposal stacks the actions full width, the action first, and names the action with its object. The Fold uses the same dialog.

Accept In a confirmation the action sits first and Cancel under it, both full width and never clipped at the largest text size; the action’s label is the verb and object the title names (Delete 2 photos, Delete file, Delete playlist); destructive confirmations are red because they declare it, not because of their label.

UI-MOB-SELECTION-BARPhone · Fold

The photo selection bar stays in reach with its count

Why. Selecting photos is a long press, and the count, Delete selected… and Clear selection are the first row of the scrolling timeline. After selecting a photo deep in the library they scroll off the top: nothing says selection is on or how many photos are chosen, and the actions are as far from the thumb as they can be. The proposal pins the same row above the tab bar and adds the count.

Accept While photos are selected a bar above the tab bar shows “N selected”, Clear and Delete…, whatever the scroll position; Delete… stays dimmed with its reason when the hub is away; leaving selection removes the bar.

UI-MOB-HISTORY-PATHPhone · Fold

History rows lead with the file name

Why. A History row’s title is the whole path cut at its end, so a deep file such as documents/work/2024/invoices/inv-2024-03-final.pdf loses its name behind an ellipsis, the one part people look for. Recent inside a folder already wraps instead. The proposal leads with the file name and moves the folders into the caption.

Accept A History row’s title is the file name, its caption the folder path inside the shared folder, then size and time; a row never loses its file name to an ellipsis; Deleted and conflict rows keep their tints.

UI-DESK-COLD-STARTDesktop

A cold start says it is starting, not that the service stopped

Why. Every launch first shows the Service stopped page (“Your files remain on disk”, Start service) while the daemon is still coming up, for up to fifteen seconds, so the first screen of a normal launch looks like a failure. The launch mark already exists for this moment. The proposal keeps the launch mark with the line “Starting Arca…” through the grace window and shows Service stopped only when the daemon really did not answer.

Accept From launch until the daemon answers the window shows the launch mark with “Starting Arca…” and no sidebar; Service stopped appears only after the grace window or a real error; a Start service press shows the same starting state until the probe succeeds, then the error line if it fails.

UI-DESK-UPDATEDesktop

The update says what it is doing and what it costs

Why. After Update and restart the button only reads “Installing…” for the whole download, stop and restart, with nothing moving and no word that sync pauses. The tray calls the same state “Arca X is ready” with an Install… button that only opens the window. The proposal uses the busy mark the app uses everywhere, “Updating to Arca X”, and one line with the consequence.

Accept While an update installs the sidebar card shows the busy mark, “Updating to Arca X” and “Sync pauses while Arca restarts.”, with no button; the tray names the same state with the same words and its button reads Open Arca because that is what it does.

UI-DESK-NOTICESDesktop · Phone · Fold

A notice has one way to be dismissed

Why. Warnings and errors carry a Dismiss link under their text and an × in the corner, both doing the same thing, so the action row spends a slot on a duplicate and the × is a 16 px target. The notice contract is shared with the phone, which draws the same pair. The proposal keeps the × (with a 32 px hit area, 44 dp on the phone) and leaves the action row to the real action.

Accept Warnings and errors show one dismiss control, the ×; the action row holds only the notice’s own action (Review, Retry now) and disappears when there is none; the × is at least 32 px on desktop and 44 dp on the phone; the swipe on the phone is unchanged.

UI-DESK-FILES-TIMEDesktop

Files rows say when the file changed

Why. The Files browser lists a name and a size, so recent work cannot be told from old files without opening each one; History, Recent and the file page already show times. The proposal adds the relative time of the last change to the second line, with the same wording History uses (“2 h ago” within a day, a date beyond). A sort control is a separate decision and is not drawn.

Accept Each Files row’s second line reads size · time of its last change in the History format; a folder row keeps its file count and size; no control is added.

UI-DESK-HISTORY-EMPTYDesktop

A filtered History that is empty offers the way out

Why. Filtering History to Conflicts is the most common filter and usually empty. Its empty state tells people to clear a control by name (“Clear Conflicts to see every change”) and leaves them to find it. The proposal says what is true and offers the same exit as a button, as the disconnected state already does with Connect to hub….

Accept An empty History caused by a filter or a folder choice says what is true in one line and offers Show all changes, which clears both; the unfiltered empty state and the offline states are unchanged.

UI-DESK-DELETE-NAMESDesktop

Deleting names what it deletes, and a deleted file is not “Current”

Why. The delete confirmation asks “Delete this file?” without saying which, while the track and playlist deletions name their target; and a row marked Deleted · recoverable opens on a tombstone version badged Current with no hint of how to get the file back. The proposal names the file in the question and shows Deleted instead of Current on the tombstone.

Accept The delete confirmation reads Delete “name”? with the file’s name; on a deleted file’s page the newest version carries the Deleted pill (not Current) and one line says to restore an older version below.

UI-MOB-PAIRINGPhone · Fold

Pairing keeps its error beside the code and has a way back

Why. A wrong or expired code becomes a bottom toast titled “Could not complete action” with Retry now, which sends the same code again and spends the failure budget, while the form keeps the digits. The address help is three sentences between the two fields, pushing the code down at large text sizes, and after “Get started” there is no way back to the welcome page that says a hub is needed. The proposal puts the message under the code, keeps the help to one line and adds Back.

Accept A rejected code shows its message under the Pairing code field, clears the cells and offers no Retry; the address help is one line (the local Wi-Fi explanation moves behind the existing details toggle); the pairing step has a quiet Back that returns to the welcome page; the Fold shows the same single column.

UI-MOB-DEVICE-STATEPhone · Fold

Navigation shows the device state and names its destinations

Why. On the phone, a hub that is away or a conflict that is open is visible only on folder rows and in a toast that is gone; the Fold’s rail shows the device state but has no labels, so Devices and History are told apart by glyph alone on the device people unfold most. The proposal puts the existing warning dot on the Settings tab when the device is not up to date and gives the Fold’s rail a caption under each icon, as the phone tab bar has.

Accept The phone’s tab bar carries a warning (or danger) dot on Settings when the device state is not Up to date, with the state in its spoken label; the Fold’s rail is 72 dp with each destination’s name under its icon and keeps the device glyph and its dot; nothing changes in the Up to date state.

Format 02

Board

One article per idea, tagged with its task ID. It carries the ID, the area (System, Desktop, Mobile, Auto), a title, why it is worth doing, a "Now" drawing of what exists, a "Proposed" drawing, and what proves it done. A mobile board adds a Fold pair beside its phone pair. Phones sit side by side; desktop, web and Fold drawings stack Now above Proposed so each keeps its full width.

Drawings

Both drawings use production and kit classes only, so the page reads as the app would. A drawing is never a screenshot and never introduces a colour or size outside the tokens.

Lifecycle

Idea: a board only. Approved: one ROADMAP Queue line of type ui with the board ID, whose accept is the board. Shipped: the board is deleted, the changelog and SPEC record it, and this kit is updated.

No visual part

Behaviour, data and infrastructure tasks live only in ROADMAP and never get a board.
