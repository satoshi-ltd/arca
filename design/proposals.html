Boards 01

UI-MOB-SHARE-DESTINATIONS

Save files remembers where you save

Mobile

Why. Sharing a file into Arca from another app always starts at the list of selected folders: the usual destination, often a subfolder such as receipts/2026, is three taps and a scroll away every time, and a receipt shared weekly costs the same effort as the first one. The proposal adds a Recent destinations section above Selected folders with up to three places this phone saved to, most used first, each showing the folder, the subfolder and how often and when it was used; one tap opens that destination with Save here ready. The alternative, preselecting the last destination and showing Save here at once, saves one more tap but makes the wrong folder a one-tap mistake, so the list keeps an explicit choice. The section is absent until something has been saved, so the first share looks as it does today.

Accept

The Save file / Save files sheet shows a Recent destinations section above Selected folders when this phone has saved shares before: up to three rows, most used first and then most recent, each naming the folder, the subfolder path when there is one and "Used N times · when"; tapping a row opens that folder at that subfolder with Save here enabled, and Shared folders still returns to the list; a destination whose folder is no longer selected on this phone is not listed; the section is absent with no history. A mobile source test covers the sheet and the data follows MOB-SHARE-DESTINATIONS.

Format 02

Board

One article per idea, tagged with its task ID. It carries the ID, the area (System, Desktop, Mobile), a title, why it is worth doing, a "Now" drawing of what exists, a "Proposed" drawing, and what proves it done.

Drawings

Both drawings use production and kit classes only, so the page reads as the app would. A drawing is never a screenshot and never introduces a colour or size outside the tokens.

Lifecycle

Idea: a board only. Approved: one ROADMAP Queue line of type ui with the board ID, whose accept is the board. Shipped: the board is deleted, the changelog and SPEC record it, and this kit is updated.

No visual part

Behaviour, data and infrastructure tasks live only in ROADMAP and never get a board.
